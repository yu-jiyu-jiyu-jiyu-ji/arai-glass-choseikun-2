調整くん（choseikun）本番デプロイ手順（WinSCP・顧客サーバー）
＋ 旧・日程調整システム設定画面との差分
作成日: 2026-10-27
================================================================================

■前提
・本番は顧客サーバー（Renderではない）
・旧「日程調整システム」（Streamlit / nittei）は全削除し、同じサーバーに調整くんを構築
・ファイル配置は WinSCP で手動


--------------------------------------------------------------------------------
1. WinSCP で一括転送してよいもの（choseikun ルート）
--------------------------------------------------------------------------------

【転送する】
・app/
・components/
・lib/
・public/（あれば）
・data/settings.json
・package.json / package-lock.json
・next.config.ts / tsconfig.json など設定ファイル
・docs/（任意・動作には不要）
・.env.example（参考用）

【転送しない／除外】
・node_modules/     … サーバーで npm install
・.next/            … サーバーで npm run build
・.env / .env.local … サーバー上で別途作成（秘密情報）
・サービスアカウント JSON … Git や不用意なコピー禁止。サーバーの安全な場所に個別配置
・.git/（任意で除外）


--------------------------------------------------------------------------------
2. ファイル配置だけでは済まない作業（旧システムの「起動の仕方」は流用不可）
--------------------------------------------------------------------------------

旧システム = Python + Streamlit
調整くん   = Node.js + Next.js
→ 入れ方・起動コマンドは作り直し。鍵・Firebase・ドメイン枠は流用可。

【サーバー上で必要な作業】

(1) Node.js（20系推奨）が入っていること
(2) サービスアカウント JSON をサーバーに配置
    例: schedule-adjustment-….json
(3) 環境変数ファイルを作成（例: .env.local または .env）
    最低限:
      CHOSEIKUN_DATA_BACKEND=firestore
      CHOSEIKUN_USE_MOCK=true
      GOOGLE_APPLICATION_CREDENTIALS=（サーバー上の JSON のフルパス）
    任意（次フェーズ）:
      GOOGLE_MAPS_API_KEY=
      GOOGLE_OAUTH_CLIENT_ID=
      GOOGLE_OAUTH_CLIENT_SECRET=
      GOOGLE_OAUTH_REDIRECT_URI=
(4) 配置したフォルダで:
      npm install
      npm run build
      npm run start
      （本番は pm2 や Windows サービス等で常時起動を推奨）
(5) ファイアウォール／IIS・nginx 等で外からアクセス可能にする
(6) 確認: https://（ドメイン）/api/health
      → ok: true と workerCount が出れば台帳接続成功

【流用できるもの】
・Firebase（台帳）そのもの ※消さない
・サービスアカウント JSON の中身
・Maps / OAuth のキー値（旧 .env から）
・ドメイン・HTTPS・FW の枠組み

【流用できないもの】
・pip / requirements.txt / streamlit run
・旧の常時起動設定（そのまま）
・施工用の画面・車両まわりの運用


--------------------------------------------------------------------------------
3. 旧システム削除前に必ず残すもの
--------------------------------------------------------------------------------

・サービスアカウント JSON のコピー
・旧 .env の値メモ（Maps / OAuth など）
・Firebase プロジェクト（消さない）
・職人マスタ（workers）データ


--------------------------------------------------------------------------------
4. 旧・日程調整「設定画面」内容と、今の調整くんとの差分
--------------------------------------------------------------------------------

【旧システムにあり、今の調整くんに「ない」もの】

■基本設定まわり
・積込時間（分） … なし（施工向け。訪問調査では未使用）
・検索範囲日数 90日（保存値・将来用） … なし
  ※調整くんは initial/extend/maxSearchDays（例: 7/7/21）で別管理
・「当日を含む週（日曜〜土曜）に限定」 … なし（段階探索日数方式）
・空き表示の上限件数 40 … なし
  ※調整くんはおすすめ枠 recommendedCount（既定3）のみ
・職人ランク候補（A,B,C,1） … なし（職人に surveyMain / 有効のみ）

■空き検索の既定値
・人数の既定 UI … なし（requireTwoWorkers＝基本2人のON/OFFのみ）
・作業時間（分）120 … なし
  ※調整くんは調査 surveyMinutes（既定45）＋ bufferMinutes（既定15）
・初期対象週（今週） … なし
・車両：なし、の設定項目 … なし（車両はスコープ外）
・仮タイトル生成（既存予定を参考） … なし
・仮タイトル書式（フォールバック） … なし
・「開いたときにこの既定で空きを自動表示」の施工候補検索UI … なし
  ※調整くんは顧客／代理入力の3ステップ＋間検索

■就業時間
・開始〜終了 07:00〜19:00 の設定値としての旧画面 … あるが値・意味が違う
  ※調整くん: workdayStartHour / workdayEndHour（既定 9〜17）＋昼休み
  ※07〜19 には現状なっていない（設定画面で変更は可能）

■移動・渋滞
・移動再計算モード（候補確定時に[移動]を張り直し） … なし
・渋滞バッファ（朝）分・時間帯 … なし
・渋滞バッファ（夕）分・時間帯 … なし
  ※調整くんにあるのは detourThresholdMinutes（ΔT・寄り道閾値）のみで別概念

■会社休日
・定休曜日 … あり（workdays。日曜OFFは近い）
・祝日休日：全祝日を自動除外 … なし
・個別休日 … なし

■その他・施工専用（調整くん方針上スコープ外）
・車両まわり全般
・施工案件（projects）用の設定
・仮押さえタイトル運用


【調整くん側にすでに近い／あるもの（参考）】

・会社住所（事務所）… あり（郵便番号・建物・座標も）
・候補刻み 60分 … あり（slotIntervalMinutes）
・基本2人 … あり（requireTwoWorkers）
・稼働曜日 … あり
・バッファ（調査後）… あり（bufferMinutes。積込・渋滞バッファとは別）
・探索日数 … あり（ただし週固定ではなく日数ベース）


【差分の見方（方針メモ）】

訪問調査の調整くんは「施工の候補検索」のコピーではない。
旧設定のうち車両・仮タイトル・積込・移動張り直し・施工用既定は、
現状スコープ外のため「無い」のが正しいものが多い。

今後、業務上どうしても寄せたい候補（要検討）:
・祝日の自動除外
・個別休日
・就業時間を 7〜19 に寄せるか（設定値の変更で可）
・朝夕の渋滞バッファを間検索に取り込むか
・空きカード上限や検索日数の拡張
